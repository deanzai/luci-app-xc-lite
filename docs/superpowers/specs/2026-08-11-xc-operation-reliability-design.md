# XC 操作可靠性与可观测性修复设计

**日期：** 2026-08-11

**分支：** `fast_select_api`

## 目标

修复四类用户可见问题：节点切换后出口 IP 不刷新、设置页重启误报错误且缺少运行恢复入口、核心资源下载卡在 99% 且无法中断、操作缺少足够日志。保持 Lua 5.1、LuCI 和 OpenWrt/ImmortalWrt 21.02–24.10 兼容性，不改变现有安全切换、快速切换和资源原子替换的安全边界。

## 当前根因

1. 出口 IP 缓存以节点和运行配置摘要作为键；切换回曾经使用过的节点时可能复用旧观察结果。节点选择、回滚和重启没有统一缓存失效点。
2. 设置页“重启服务”实际调用完整 `switch`，把重启、监听等待和两次真实联网检查绑定在一起。公网检测失败会让页面显示失败，即使 Xray 已经启动或随后被 procd 拉起。
3. 资源更新由后台 `xc asset-update` 持有持久状态。平台层没有取消标记到 curl 子进程的控制通道，前端只能看到最多 99% 的下载状态；刷新页面不会改变后台任务。
4. 现有结构化日志已具备大小限制和脱敏，但许多入口只有完成日志；资源任务、开始阶段、下载进度、重启阶段和恢复阶段无法定位。

## 方案与范围

沿用现有 runtime 锁、状态文件、`assetjob` 后台任务和 XC JSON 日志，不引入新的任务队列或日志系统。所有改动只围绕四个反馈，避免把只读状态轮询写成高频日志。

## 运行时与出口 IP

- 在安全切换提交活动节点、快速切换改变 Xray balancer、回滚和服务重启前清除受保护的出口 IP 缓存。
- 运行操作期间 status 不观察出口 IP；操作结束后的下一次 status 轮询重新通过本地 SOCKS 访问配置的检测 URL。
- 只有通过现有严格 IPv4/IPv6 校验的结果才写入缓存；缓存继续受节点、配置摘要和 TTL 约束。
- 快速切换的节点页成功回调继续刷新 active 状态；设置页通过独立 status 轮询获得新的出口 IP。

## 独立重启与恢复

设置页的“重启服务”改为独立 `restart-service` 后台操作，不再复用 `switch`。

`restart-service` 在 runtime 锁内：

1. 先处理已有可恢复事务；
2. 使用当前已准备好的运行配置执行 `restart_prepared`；
3. 检查服务状态以及 SOCKS/HTTP 两个监听端点；
4. 成功后清除出口 IP 缓存并返回 `restarted`。

该操作不执行公网真实连接检查；“测试当前连接”继续负责 SOCKS/HTTP 的真实请求验证，因此公网检测失败不会伪装成核心重启失败。

新增“恢复运行状态”入口和对应 action/CLI。恢复操作处理待恢复事务，必要时使用当前有效配置重启并验证监听；失败返回稳定的 `recovery_required` 或阶段错误码，同时保持事务文件和错误日志供下一次恢复，不伪装成成功。状态页在服务停止、恢复未知或存在待恢复事务时显示该入口。

## 资源下载、取消与进度

新增仅接受当前 `job_id` 的资源取消 action。取消流程使用固定的受保护取消标记：

1. 前端请求取消当前任务；
2. `assetjob` 写入当前 job 的取消标记；
3. 平台下载等待循环检测该标记，终止 curl、回收子进程并返回取消结果；
4. worker 删除临时文件，写入 `asset_update_cancelled` 终态，释放任务锁。

取消标记、任务状态文件、临时路径和可执行参数均为固定白名单值，不接受任意 URL、路径、PID 或命令。下载超时仍有上限；超时、取消、下载失败和安装失败使用不同稳定错误码。有效资源只在下载成功且后续安装成功后原子替换，任何异常都保留当前有效资源。

资源状态继续返回阶段、已下载字节数、总字节数和百分比。核心页进行中显示阶段和“已下载/总大小”，提供取消按钮；下载阶段最高显示 99%，进入安装阶段显示安装中，只有完成后显示 100%。刷新页面时恢复仍然活跃的任务，终态显示由当前操作决定，日志保留完整历史。

## 统一操作日志

复用 `/var/log/xc.log`、现有日志锁和 JSON 结构。每项有副作用或可能耗时的操作记录开始、关键阶段和结束事件：

- 安全切换、快速切换、重启、恢复、回滚；
- 单节点测速、全部测速产生的各节点测速请求和停止操作；
- 导入预览、导入提交；
- 核心上传、激活、回滚、删除；
- Xray/GeoIP/GeoSite 更新、回滚和取消；
- 访问控制应用。

资源下载专门记录：

- 下载开始：资源类型、固定 source ID、任务 ID；
- 下载进度：25%、50%、75%、99% 等阈值最多各记录一次，包含已下载/总字节数；
- 进入安装、成功、失败、取消、超时：阶段、稳定错误码和耗时；
- 无法取得总大小时仍记录已下载字节数和当前阶段。

日志字段只允许节点内部 ID、资源 kind/source、阶段、结果、稳定错误码、耗时和字节数等白名单字段。沿用现有 URL、凭据、UUID、raw/config 字段脱敏规则，不记录原始响应或完整下载地址。只读 status/log 轮询不记录事件。

前端操作提示优先使用后端稳定阶段和错误信息，不把所有失败折叠为同一个“错误”；日志页继续使用现有来源、级别筛选和安全文本渲染。

## 错误处理与兼容性

- 所有新增 action 保持 POST-only、固定参数和既有 HTTP 错误映射。
- 所有新增 runtime/assetjob 分支在锁、状态文件和子进程异常时释放资源；失败状态可重试或恢复。
- 不删除有效运行配置、有效资源或核心版本；恢复失败明确暴露恢复需求。
- Lua 保持 5.1 语法；浏览器 JavaScript 保持现有 ES5 兼容约束。

## 测试设计

先写失败回归测试并确认失败原因，再实现最小改动：

1. `test_runtime.lua`：验证切换/快速切换/回滚/重启失效出口 IP 缓存，重启不调用公网检查，恢复入口处理待恢复事务。
2. `test_platform_process.lua`：验证取消标记能终止下载子进程、回收进程并拒绝非固定取消路径。
3. `test_assetjob.lua`：验证取消、超时、下载失败、安装失败均进入正确终态、清理临时文件并释放锁；验证下载进度日志阈值。
4. Controller Lua 测试：验证重启、恢复、资源取消的路由、方法、参数白名单、稳定响应和日志事件。
5. `test_status.js`：验证独立重启 action、恢复按钮、阶段反馈和状态轮询。
6. `test_core_ui.js`：验证资源下载字节/阶段展示、取消按钮和取消/失败终态。
7. 日志相关测试：验证所有操作至少记录开始与结束，敏感字段不泄露，下载阶段日志包含受限进度信息。

完成后运行完整 Lua/Node 宿主测试、翻译与包检查、`git diff --check`；具备目标构建环境时再构建对应 IPK 并检查包内容。设备验收目标为 `192.168.13.1`，不记录设备凭据或敏感配置内容。

## 验收标准

- 切换到曾使用过的节点后，设置页出口 IP 重新观察，不显示旧缓存；服务重启后也重新观察。
- 设置页重启只验证核心服务和监听，不因公网检测失败误报；事务异常时有可点击恢复入口。
- 资源下载卡在 99% 时可取消，后台 curl 被终止，页面和日志显示取消/失败原因，刷新后不再残留活跃任务。
- 任一纳入范围的操作在日志页能看到开始、阶段和结束/失败事件；下载日志包含开始、受限进度、安装和终态。
- 既有快速切换、安全切换、回滚、核心管理、资源原子替换、日志脱敏及兼容性测试保持通过。
